# Turn CI Back On Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** GitHub Actions CI runs every check on every PR and on pushes to `main`, and is the gate a PR must pass; `scripts/verify.sh` becomes a recommended local check.

**Architecture:** The existing `.github/workflows/ci.yml` (verify-signatures, docs-links, build, e2e, container-smoke) is re-enabled, gains the one check `verify.sh` runs that CI doesn't (shipped migrations), and cancels superseded runs. The owner makes its jobs required on `main`. The private pre-push gate is retired and the repo's own `.githooks` (signature checks) become the hooks again. Docs stop saying CI is off.

**Tech Stack:** GitHub Actions, bash, `gh`.

**Spec:** `docs/superpowers/specs/2026-11-19-open-source-roadmap-design.md` (Gate 1, item 1)

## Global Constraints

- At most 10 changed files per PR; docs in their own PR (`AGENTS.md`).
- The repo is public, so GitHub-hosted runner minutes are free.
- CI is the binding gate; running `verify.sh` before pushing is recommended, not enforced.
- Required checks on `main` are an owner step in the repo's GitHub ruleset, named in the PR's heads-up.
- The repo's `.githooks` keep checking commit signatures locally.
- No branch names, task numbers or plan paths in commits or PR bodies.

## Review Focus

1. **No release tag in the CI checkout** → `check-shipped-migrations.sh` exits 0 silently and the guard does nothing. Expected: the CI step fails if no `v*` tag is reachable. Pinned in Task 1 (step 3 and the step-5 check of the log).
2. **Two quick pushes to one PR** → two full runs, including e2e, both finish. Expected: the older run is cancelled. Pinned in Task 1 (step 5).
3. **Push to `main`** → a merge to `main` must never be cancelled by a later merge. Expected: cancellation applies to PR runs only. Pinned in Task 1 (the `cancel-in-progress` expression).
4. **e2e on a 2-core runner** → flaky timeouts, which locally needed `--workers=1`. Expected: green on the first run; if it times out, set `--workers=1` in the CI step, not in `playwright.config.ts`. Checked in Task 1 (step 5).
5. **A push after the gate is retired** → the push still runs the repo's signature check. Pinned in Task 3 (step 2).

### Task 1: CI runs the migration guard and cancels superseded PR runs (PR 1)

**Files:**
- Modify: `.github/workflows/ci.yml`

**Interfaces:** none.

- [ ] **Step 1: Add a top-level `concurrency` block** after `permissions`:
  `group: ci-${{ github.ref }}` and `cancel-in-progress: ${{ github.event_name == 'pull_request' }}`, with a one-line comment: why only PRs (a run on `main` is the record for that merge).
- [ ] **Step 2: Fetch tags in the `build` job.** It already checks out with `fetch-depth: 0`. Add `fetch-tags: true` to that checkout so `git describe` sees the `v*` tags.
- [ ] **Step 3: Add a step to `build`, before `npm ci`:**
  ```yaml
  - name: Shipped migrations are unchanged
    # The script passes when it finds no release tag, so prove one is visible first.
    run: |
      git describe --tags --abbrev=0 --match 'v*'
      bash scripts/check-shipped-migrations.sh
  ```
- [ ] **Step 4: Commit** (`ci: check shipped migrations and cancel superseded PR runs`), run `scripts/verify.sh --e2e`, push, open the PR into `main` with skill writing-pr-descriptions. **Heads-up** in the body: after merge, the owner makes the checks required (Task 2). Review tier: **Skim**.
- [ ] **Step 5: Verify on GitHub.**
  - `gh pr checks <n> --watch`. Expected: all five jobs pass (verify-signatures, docs-links, build, e2e, container-smoke).
  - `gh run view <run-id> --log | grep -A1 'Shipped migrations'`. Expected: the log shows a tag such as `v0.5.2`.
  - Cancellation is checked the first time any PR gets a second push while its run is going (no extra commit for it): `gh run list --branch <branch> -L 2`. Expected: the older run shows `cancelled`.
  - If e2e times out, add `-- --workers=1` to the e2e step's `npm run test:e2e` with a why-comment, and recheck.
